01

Introduction: From NAND to Tetris

Overview

This foundational section explores the building blocks of computer systems, starting from basic logic gates and working up to more complex digital circuits. The journey begins with understanding how simple NAND gates can be combined to create all other logic gates and eventually entire computer systems.

NAND Gate - The Universal Gate

The NAND (NOT-AND) gate is considered universal because any boolean function can be implemented using only NAND gates. This makes it a fundamental building block for all digital logic.

Multiplexer (MUX)

A multiplexer is a combinational circuit that selects one of several input signals and forwards it to a single output line. The selection is controlled by a set of select lines, making it essential for data routing in digital systems.

Active High Latch

Latches are fundamental memory elements in digital circuits. An active high latch stores one bit of information and maintains its state until a new input is provided when the enable signal is high.

Flip-Flop

Flip-flops are edge-triggered memory elements that change state only on clock transitions. They are the building blocks of registers and counters, essential for sequential logic circuits.

Integrated Circuits

Understanding how these logic elements are physically implemented in integrated circuits provides insight into the transition from theory to practical hardware implementation.

Lessons Learned Writing a RISC-V

Building a RISC-V is an intimidating and ultimately rewarding experience in terms of getting your foot into the FPGA world. Coming from a software background I think there are many considerations that can help speed up the learning process. I will go over my process when designing and implementing it into hardware and some tips that may help speed up your progress.

I started my design process trying to understand how the RISC-V architecture work. I wrote up a diagram and broke the design up into its smallest components. After reading literature on how the processor works I came up with an interpretation to work off of. The design at its most basic components are basic logic gates that equate to transistor circuits.

Abstractly this is my internal workflow

  • Blackbox entity with defined inputs & outputs
    • Understand the constraints, functionality, and how to formally verify it.
  • Breakdown functionality into...
    • Sequential processes: Think about a single thread process similar to how you would approach conventional programming: a → b → c
    • Concurrent processes: What can or should be done simultaneously.
  • Writing processes
    • What does each process do in terms of logical operations (and, or, xor, if, for)?
    • Write each process in terms of logic design.
  • Understand synthesis
    • While we think in logical operators, the tool will translate your logic to real circuits.
    • While not guaranteed, assume the tool pattern-matches operators to respective circuits.
    • You can design basic flip flops and gate logic in LTSpice to build intuition.

Now I take this flow and apply it recursively from the top level of the design I am building.

  • Build a RISC-V → Divide into control and datapaths.
  • Build a datapath → Break into sequential and concurrent components.
  • Build a component (datapath/register file) → Break into selectors (mux) and registers (FFs).
  • Build a subcomponent (mux) → Read how it works and optionally prototype in LTSpice.
  • Build basic logic like muxes and flip flops first, then scale upward.

Once you build the most basic component, build its neighbors and understand how it works (like a binary tree). Eventually you will build up a toolkit of components at different layers of abstraction. Eventually the goal is to build bottom-to-top into larger functionalities (filters, FFTs, memory structures, protocols, interfaces).

After you build a pathway down from the top level, work on simplifying and optimizing each piece of the architecture from bottom to top.

Finally, we can look at design paradigms like adding multi-cycle functions and pipelining.

This isn't programming; this is circuit design. Concurrency is your friend!

Remember when debugging

  • RTL uses structures not object-oriented hierarchies. It’s a circuit, not sequences (DRC errors will be imminent).
  • Pattern match and trace.
  • Organize using entities and simplify the problem every step of the way.
  • Beware of clock domain crossing.

Other tips / tricks

  • Always think about how to simplify or optimize your workflow.
  • Leverage Python, sed/awk, and other tools for verification and design.
  • Build and save reusable work to accelerate future projects.
  • Auto-generate build scripts, project files, register definitions, and verification code where possible.
