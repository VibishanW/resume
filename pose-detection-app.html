Joint For Joint (j4jweb)

Baseline BlazePose implementation for benchmarking hardware acceleration

Project Overview

The Joint For Joint (j4jweb) project is a React-based web application that implements Google's BlazePose model using TensorFlow.js. This application serves as a baseline software implementation to test and benchmark the performance of BlazePose's CNN model before comparison against my hardware-accelerated implementation on AMD Versal AI Engines.

By creating this software baseline, I was able to establish performance metrics (FPS, latency, accuracy) that could be directly compared with the hardware-accelerated version developed in my master's thesis.

Implementation Details

Real-Time Pose Detection

The core pose detection functionality uses TensorFlow.js with the WebGL backend to run BlazePose inference directly in the browser:

// Initialize TensorFlow.js with WebGL backend await tf.setBackend("webgl"); await tf.ready(); // Load BlazePose model const model = poseDetection.SupportedModels.BlazePose; const detectorConfig = { runtime: "tfjs", modelType: "full" }; detector = await poseDetection.createDetector(model, detectorConfig); // Run inference on video frames const poses = await detector.estimatePoses(videoElement);

Skeleton Drawing

The application visualizes detected poses by drawing keypoints and connections on a canvas overlay:

  • 33 body keypoints tracked per person
  • Confidence threshold of 0.3 for keypoint visibility
  • Pre-defined skeleton connections matching BlazePose topology
  • Real-time canvas rendering synchronized with video frames

Performance Benchmarking Mode

The SoftwarePose component includes a recording mode that captures 10 seconds of pose detection data for performance analysis:

  • Tracks total frames processed during the recording period
  • Calculates average FPS for baseline comparison
  • Measures inference latency per frame
  • Provides consistent testing methodology for hardware comparison

Purpose & Learning Objectives

Baseline Establishment

This software implementation served as the control baseline for my master's thesis on hardware-accelerated pose estimation. Key measurements included:

  • Software-only inference FPS using WebGL backend
  • Latency characteristics of browser-based TensorFlow.js
  • Accuracy of keypoint detection using full BlazePose model
  • Power consumption and thermal characteristics

What I Learned

  • Browser-Based ML Deployment: Understanding the capabilities and limitations of running deep learning models in web browsers using TensorFlow.js
  • Real-Time Computer Vision: Implementing efficient video processing pipelines with requestAnimationFrame for smooth performance
  • WebGL Backend: Learning how TensorFlow.js leverages WebGL for GPU acceleration in the browser
  • Performance Profiling: Developing methodologies to measure and compare inference performance across different platforms
  • React & Hooks: Using modern React patterns (useRef, useEffect, useState) for managing video streams and model inference
  • Canvas Rendering: Efficient 2D graphics rendering for skeleton visualization overlaid on video

Comparison with Hardware Acceleration

The baseline metrics from this software implementation provided critical comparison points for my hardware-accelerated version:

  • Software (WebGL): ~15-25 FPS on typical laptop GPU
  • Hardware (AI Engine): Targeted 60+ FPS with lower latency
  • Demonstrated the performance gains achievable through dedicated AI acceleration hardware
  • Validated the need for hardware acceleration in real-time, resource-constrained applications

Technical Challenges & Solutions

Camera Access & Streaming

Implementing robust camera access using the MediaDevices API with proper error handling and fallbacks for different browser implementations.

Frame Synchronization

Ensuring the pose detection loop stays synchronized with video frame updates using requestAnimationFrame for optimal performance.

Canvas Overlay

Layering a transparent canvas over the video element with proper z-index management to enable skeleton drawing without interfering with the video stream.

Performance Optimization

Balancing detection accuracy with frame rate by tuning model parameters and optimizing drawing routines.

Key Takeaways

Building this baseline BlazePose implementation was instrumental in understanding the full ML inference pipeline from model loading to real-time visualization. It provided hands-on experience with:

  • End-to-end ML application development in the browser
  • Performance benchmarking methodologies for ML models
  • Real-time video processing and computer vision
  • The gap between software and hardware acceleration capabilities
  • Practical considerations for deploying pose estimation in production

Most importantly, this project established the baseline performance that made my hardware acceleration thesis work quantifiable and meaningful.
